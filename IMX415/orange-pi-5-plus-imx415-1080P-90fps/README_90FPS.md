# IMX415 1080P 90FPS 模式开发总结

## 1. 开发目标
在橙派 Orange Pi 5 Plus (RK3588) 上实现 IMX415 摄像头的 1080P @ 90FPS 预览支持。

## 2. 代码修改内容

### 2.1 内核驱动修改 (`imx415.c`)
- **新增模式定义**：在 `supported_modes` 数组起始位置添加了 1080P 90FPS 模式，使其成为默认模式。
- **寄存器配置**：
    - 参考 `.ism` 文件移植了完整寄存器列表 `imx415_linear_12bit_1932x1096_90fps_regs`。
    - **关键调整**：设置 `0x3031 = 0x00` (10-bit AD) 和 `0x3032 = 0x00` (10-bit Output)。
- **格式定义**：
    - `bus_fmt` 设置为 `MEDIA_BUS_FMT_SGBRG10_1X10`。
    - `bpp` (位深) 设置为 `10`。
- **MIPI 频率**：设置为 `1782Mbps` (`mipi_freq_idx = 5`)。

### 2.2 编译配置修改 (`noble.sh`)
- 将 `KERNEL_BRANCH` 更新为 `orange-pi-5-plus-imx415-1080P-90fps`。

## 3. 调试过程与结论

### 3.1 遇到的问题：ISP 输出全黑
- **现象**：通过 `/dev/video11` (ISP 节点) 抓取的 NV12 图像全是 0，哪怕曝光拉到最大。
- **排查步骤**：
    1. **绕过 ISP 抓 RAW**：从 `/dev/video0` 直接抓取 10-bit Bayer 数据，通过 Python 脚本解码确认原始信号正常。结论：Sensor 及传输链路 OK。
    2. **对比位深**：最初尝试 12-bit 输出但 ISP 不支持或 IQ 不匹配，随后切换到 10-bit 模式。
    3. **手动模式测试**：停止 `rkaiq_3A.service` 后，手动设置曝光和增益，ISP 节点开始有非零数据输出，能抓取到可见图像。

### 3.2 结论
- **硬件与驱动**：1080P 90FPS 10-bit 模式硬件通路完全走通。
- **软件瓶颈**：Rockchip 的 3A 引擎 (`rkaiq`) 目前不支持该模式的自动曝光/白平衡。由于缺乏针对 10-bit 90fps 模式的 IQ 匹配参数（如 Black Level 扣除值），`rkaiq` 会将画面完全处理为黑色。

## 4. 后续任务
- 适配 `rkaiq` IQ 文件，或者在 3A 运行状态下手动校准 IQ 参数。
- 进一步优化 90FPS 下的画质体验。
